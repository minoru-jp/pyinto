# pyinto Changelog

Development changes for 0.0.1. This is not a formal release history.


## 0.0.1 (Alpha, unpublished)

Initial development setup and Construct experiments after the design shift.

version: 0.0.1


Added:


- In Iteration 49, exposed finite Construct variant domains (`VARIANTS` / `variant_domain()`) in the Model and added registration-time rejection of invalid variant names and omitted `default` variants that do not exist. Structural projection now requires an explicit variant for multi-variant or open-domain Constructs. Added `variant @= '*'` to match any variant, exact-variant precedence, and duplicate rejection, while preserving Composition's Template/Slot chaining and Admission checks. Open variant domains such as `IntrinsicCall` remain unenumerated.
- In Iteration 48, added Target Pack declarations `pack_semantics` (`preservation`/`projection`) and `pack_unhandled` (`error`/`traverse`) to Shikumi and the Registry. A Structural projection Target can explicitly choose `traverse` for unregistered Realizers and continue visiting descendants. Projection does not require execution-semantic `supports` checks, but Admission registration still validates the entire Model. Preservation and Composition retain their strict defaults. Added regression coverage using a non-text Target that extracts only function names and return types.
- In Iteration 47, introduced Shikumi declarations selecting Composition or Structural Realizer dispatch per Target Pack and Target-owned Artifact Sessions. Preserved Composition's deferred Template/Slot chain; `TextArtifactSession` performs final string rendering on the Target side. Structural dispatch visits all Constructs in `Model.parts()` order, and `visit` callbacks modify Target-specific state. After dispatch, the Host calls `finish()` and receives an artifact of arbitrary type. Kept the Model, Frontend, and Admission unchanged and verified C, development-only Python, and new non-text Targets.
- In Iteration 46, added restricted support for typed `*args` in top-level user-defined functions. Variadic `TupleType`, `ParameterRole.VARIADIC`, `FunctionSignature.variadic_parameter`, and extra positional arguments in the existing `FunctionCall` preserve default/keyword binding for fixed parameters, source-order evaluation, and tuple typing. The body can access the variadic tuple with `len`, `sum`, and `for`; Target realization of variadic tuples is an explicit new Admission obligation. Reject dynamic argument unpacking, variadic function values, nested functions/methods with variadics, and `**kwargs`. No new C Realization was added; existing Interface Mapping behavior remains.
- In Iteration 41, added Shikumi parent/child declarations `@maps(function)` / `@signature(...)` and `factory @= ...`, and an `InterfaceMappingRegistry.from_declarations()` API that converts them to existing function Mappings. Reuses the existing routes for multiple signatures, named arguments, defaults, statically typed variadic positional arguments, and ambiguity rejection. Migrated the external Device example. Function objects are restricted to their defining module name; re-exports and class/method Mappings were not extended. Existing Frontend and Target realization contracts are unchanged.
- As the Iteration 40 external Interface function Mapping extension, added `InterfaceVariadicParameter` for static variadic positional arguments and explicit registration of multiple signatures under one function name. Argument expressions are normalized just once regardless of candidate count; only the uniquely matching signature's factory runs, selected by type, arity, names, and defaults. Explicitly reject duplicate registrations, no match, ambiguous matches, type mismatches, dynamic argument expansion, and side-effecting argument reorderings whose evaluation order cannot be preserved. The Model, Admission, Target realization rules, and the previously accepted single-signature cases are unchanged.
- Following Iteration 38, published `InterfaceParameter` to declare external Interface function Mapping parameters by name, value type, and trailing immutable literal default. Ordinary Python positional, keyword, and mixed calls normalize into Model arguments in declaration order. Reject unknown, duplicate, missing, type-incompatible, or unpacked arguments, and reorderings of side-effecting expressions that cannot preserve evaluation order. Retained the old positional-only Mapping acceptance, removal of `_force`, and existing Model/Target contracts.
- Extended absolute imports in the Python Source Adapter: `import module[.submodule] [as alias]` and `from package import submodule [as alias]` in the initial import section now resolve names statically against explicitly registered external APIs. Multi-level attribute function calls normalize to the same Interface Mapping. Module name collisions, unregistered names, and dynamic attribute paths are explicitly rejected. Model semantics, C Target Realizations, and the policy of never executing Python source are unchanged.
- In public-surface redesign step 3, added Shikumi `@naming` for declaring Target naming rules with a no-argument decorator marker. It uses the same `NAMING` information as `naming @= True` and retains class-level exclusion from `@realizes(element)` and legacy role descriptors, duplicate naming-rule rejection per Target, and the `requirement_line` Slot constraint. The C Target and development Python Realizer would migrate from legacy syntax in a later step; Model, Frontend, and Target conversion coverage did not change.
- In public-surface redesign step 2, added Shikumi `@realizes(element)`. Public Host Constructs, direct Builtin Call element `builtin.PrintCall`, and type `ValueKind` / `PortType` use the same keys in the existing Registry routes for Constructs, Calls, and type spellings. Kept `print` Call separate from `PrintValues`, and rejected old/new duplicate registrations, invalid targets, unsupported Contracts, and invalid Slots. Existing `handles`/`binds`/`spells`/`naming`, C/Python Target implementations, and Frontend acceptance remained unchanged. `@naming`, removal of legacy descriptors, and other public Call elements were deferred.
- In public-surface reorganization step 1, added `pyinto.interfaces.language` / `builtins` and `pyinto.model.value_types`. These re-export existing Construct classes and `ValueKind` enum with identity preserved, providing Target authors with entry points that do not expose internal file layout or string keys for types. The conversion API, Shikumi role descriptions, C Target, and the Model's semantic and acceptance/rejection contracts remain unchanged. `@realizes(element)` and `@naming` were deferred pending target-identity auditing.
- In Model expressiveness expansion step 12 (Iteration 35), enabled statically normalized, explicitly typed new variable declarations inside `if/else`, `while/else`, `for/else`, and `with` bodies, using existing `Initialize` / `Block` (FRT_071). References are allowed only after declaration in the same or nested body, and rejected after the body, in other clauses, or before declaration.
- In Model expressiveness expansion step 11 (Iteration 34), enabled `for` to introduce one implicit variable when the element type is known (CST_073 / FRT_070). Separated an introduction flag on `IterationEntry` from the prerequisite `iteration.binding.introduced` Admission contract and avoided artificial initialization on empty iteration. Existing iteration over previously declared variables remains valid; references from outside the loop or its `else` clause are not accepted.
- In Model expressiveness expansion step 10 (Iteration 33), added `SliceValue` for typed lists and strings (CST_072 / FRT_069). It preserves omitted bounds, negative steps, index clipping, and the runtime error for a zero step. Shallow list copying and Unicode string selection are independently registered as semantic obligations for Admission.
